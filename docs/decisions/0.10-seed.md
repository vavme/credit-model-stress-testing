# 0.10 Project-Wide Seed

**Phase:** 0 (Scope Lock & Setup)
**Tag:** [You]
**Status:** Done
**Decided:** 2026-09-13

## The decision

`42`. One value, used everywhere: the train/val/test split, every corruption function (per 0.8's `ExperimentConfig.seed` field), and model training.

## Why

Without a fixed seed, the numbers in this repo can't be reproduced next week, let alone by someone else running it, and reproducibility is one of the concrete things evaluators actually check by cloning the repo and running it, not just reading the write-up. `42` specifically has no significance beyond being a conventional, easy-to-recognize default, the choice that matters is fixing *one* value everywhere, not which value.

## How it shows up in code (Phase 3 onward)

- Replaces the placeholder pattern (`SEED = None`) that was flagged until this was decided. From here on it's `SEED = 42`, used directly.
- Threads through `ExperimentConfig.seed` (0.8) into every corruption function (pure and seeded) and into model training for both the baseline and XGBoost.
- Because it's a single fixed value, not a set of seeds to average over, this project doesn't report seed-to-seed variance; that's a deliberate simplicity trade-off consistent with the rest of Phase 0's scope decisions, not an oversight.
