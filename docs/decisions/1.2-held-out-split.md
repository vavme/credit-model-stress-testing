## The decision

No new judgment call here. The method was already locked in 0.4 (one stratified 60/20/20 train/val/test split, carved once from `application_train.csv`) and 0.10 (seed 42). This item is the moment the split actually got made and the test set got sealed.

## What got built

- `src/data/split.py` holds a pure `make_split(df, seed=42)` and a `run()` entry point that writes `data/processed/{train,val,test}.csv`.
- Two chained stratified `train_test_split` calls on `TARGET`: first 60% train vs 40% temp, then temp split 50/50 into val and test.
- `tests/test_split.py` checks sizes, that the three splits are disjoint and cover every row, that stratification holds, and that the same seed gives the same split.
- Commit `7ed5176`, "Add stratified 60/20/20 split (1.2/1.3), reconcile raw data location".

## Result

| Split | Rows | Share | Default rate | Positives |
|---|---|---|---|---|
| train | 184,506 | 60% | 8.07% | ~14,895 |
| val | 61,502 | 20% | 8.07% | ~4,965 |
| test | 61,503 | 20% | 8.07% | ~4,965 |

Source: 307,511 rows in `application_train.csv`, 8.07% default rate overall. The default rate held in all three splits (this also closes 1.3).

## Why this matters

- The test file now exists on disk, so "no peeking" stops being a plan and becomes a discipline. From here until Phase 5, nothing reads `data/processed/test.csv`: no EDA, no tuning, no feature selection against it.
- EDA (1.4, 1.6) and the feature shortlist (1.5) use `train.csv` only. `val.csv` is for model selection in Phase 4. Neither the raw file nor the test file should be used to decide anything.
- Because the split is seeded and the function is pure, anyone can regenerate the exact same files from the raw CSV.
